# OF-Scraper reference

Everything the program can be told to do, written for coding agents (and
people) who need an answer without tracing the code. The user docs (the
`docs` submodule) are upstream's and don't cover this fork's additions.

| File | Covers |
|---|---|
| [cli.md](cli.md) | Commands, `--action` modes, and every command-line option: names, type, default, which commands accept it, its `config.json` fallback, where it's defined |
| [config.md](config.md) | Every `config.json` key: default, getter, older key names still read, the environment default behind it, the option that overrides it |
| [env.md](env.md) | Every built-in default in `ofscraper/utils/of_env/values/` and the environment variables that override them, plus the backoff settings |
| [placeholders.md](placeholders.md) | The names usable in `dir_format`, `file_format`, `metadata` and text file names |
| [database.md](database.md) | The tables in each creator's `user_data.db`: columns, unique keys, and what writes each row |

Those five files are generated by `scripts/reference/build_reference.py` from
the code, with descriptions from `scripts/reference/notes.py`.
`test/test_reference.py` fails when they're out of date or when something has
no description. This file is written by hand.

## Where a setting's value comes from

For one run, a setting is decided in this order; the first that gives a value
wins:

1. **A command-line option**, when the option has a `config.json` fallback
   ([cli.md](cli.md) lists them). `ofscraper/utils/settings.py`
   `merged_settings` does the merge. Most use `option or config`, so an
   option set to a false value (0, an empty string) falls through to the
   config. Flags that only turn something on can't turn a config setting off.
2. **`config.json`**, read by the getters in `ofscraper/utils/config/data.py`
   and `ofscraper/utils/paths/common.py`. A getter also accepts older key
   names and locations ([config.md](config.md)).
3. **The built-in default**, used when the key is missing or empty. It's
   read with `of_env.getattr`, so an environment variable can change it
   ([env.md](env.md)): the listed variable (usually `OFSC_<NAME>`) when the
   defaults load, or the bare key
   name on every lookup. Environment variables change only defaults; they
   don't override a value that's in `config.json`.

Environment variables come from the process, then a `.env` file found by python-dotenv, which searches upward from `ofscraper/utils/of_env/` (from the working folder only in the standalone binaries, the REPL or a debugger),
then the files in `advanced_options.env_files`, each overriding the last. The `--env-files` option isn't loaded at present.

Settings without a `config.json` key (the backoff values, timeouts, API
URLs, and most of [env.md](env.md)) can only be changed through the
environment.

Which site a run uses: `--site`, else `site.json` in the profile folder
(`{"site": "fansly"}`), else OnlyFans (`ofscraper/sites/__init__.py`).

## What writes files

- **`config.json`** is rewritten from the getters when its keys differ from
  the current schema (`auto_update_config`). A getter's return value is what
  gets saved, so a getter must return what belongs in the file. The
  interactive Config menu also writes it.
- **`auth.json` / `fansly_auth.json`** are written by the Auth menu and the
  login prompts.
- **Each creator's `user_data.db`** is written by any scrape: the
  `download`, `like` and `unlike` actions, `manual`, the `*_check` commands
  and `metadata`. See [database.md](database.md) for which rows each writes,
  and for the backups made beside it.
- **Media** go under the save location through `dir_format`/`file_format`;
  downloads are written as `.part` files (in `advanced_options.temp_dir` when
  set) and moved into place. `--no-auto-resume` deletes leftover `.part`
  files instead of resuming them.
- **`db --export PATH`** writes a CSV. `recover_collisions --apply` resets
  `downloaded` flags and writes an undo file beside the database.
- **Logs** go to the `logging` folder, and the cache to the profile's cache
  folder; `--no-cache` and `--no-api-cache` stop cache writes.

## Default folder layout

```
{home_directory}/.config/ofscraper/        config home (--config changes it)
├── config.json
├── logging/                              <profile>_<date>/ofscraper_<profile>_<time>.log
│                                         (one file per day when rotate_logs is off)
└── main_profile/                         one folder per profile, always ending in _profile
    ├── auth.json                         OnlyFans credentials
    ├── fansly_auth.json                  Fansly credentials
    ├── site.json                         the profile's site, when it isn't OnlyFans
    ├── cache_sql/ or cache_json/         API and scan cache (advanced_options.cache-mode)
    ├── locks/                            lock files
    └── .data/<model_id>/                 metadata template {configpath}/{profile}/.data/{model_id}
        ├── user_data.db                  (plus -wal and -shm files)
        └── backup/                       rotating copies and pre-migration backups

{home_directory}/Data/ofscraper/           file_options.save_location
├── <model_username>/<responsetype>/<mediatype>/<filename>.<ext>
└── Fansly/                               Fansly runs save under here
```

The media path comes from `file_options.dir_format`
(`{model_username}/{responsetype}/{mediatype}/`) and `file_options.file_format`
(`{filename}.{ext}`); see [placeholders.md](placeholders.md).

## Features only this fork has

Upstream's docs don't cover these:

- **Fansly** as a second site: `--site`, the profile's `site.json`,
  `fansly_auth.json`, Fansly posts, messages and purchases, HLS/DASH video,
  and livestream recording (`--live`, `--live-watch`, `--live-interval`,
  `--live-max`, `--live-chat`). Fansly media save under `<save location>/Fansly`
  and Fansly databases carry a `site` row in `schema_flags`.
- **`file_options.filename_collision`** (environment default
  `FILENAME_COLLISION_DEFAULT`): what happens when two media would get the
  same file name.
- **`recover_collisions`** (`python -m ofscraper.commands.recover_collisions`)
  to repair databases where different media were recorded under one path;
  see `COLLISION_RECOVERY.md`.
- **`scripts/creator_names.py`** to list and record the usernames a creator
  account has had.
- **`OF_READ_TIMEOUT`**, a default read timeout for requests, and
  **`LABELS_CONCURRENCY`** for label scans.
- Behaviour changes listed in the release notes, e.g. `--before`/`--after`
  accept `MM/DD/YYYY` and relative dates, a failed run exits with status 1,
  and command-line mistakes print a usage message.

## Keeping this up to date

A change that adds, renames or removes a command-line option, `config.json`
key, environment default, placeholder or database column must update
`scripts/reference/notes.py` and regenerate the files:

```bash
PYTHONPATH=. .venv/Scripts/python scripts/reference/build_reference.py
```

`test/test_reference.py` checks both, so CI fails until it's done.
